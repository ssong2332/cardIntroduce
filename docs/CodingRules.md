# CodingRules — 카드 인트로듀스 (cardIntroduce)

> 소유자: 사용자 | 최종 수정: 2026-09-07

## 금지

- 기존 코드 스타일과 다른 새 스타일 도입 금지 (주변 코드를 따른다).
- 요청 범위 밖 파일 수정 금지.
- 주석으로 변경 이력·자기 설명 남기기 금지 (코드가 못 보여주는 제약만 주석으로).
- 테스트 없이 "동작 확인됨" 보고 금지.

## 규칙 (언어 확정 후 채운다)

| 항목 | 규칙 |
|---|---|
| 네이밍 | 변수/함수는 camelCase, 클래스는 PascalCase, 상수는 UPPER_SNAKE_CASE |
| 포맷터/린터 | 2 spaces 들여쓰기, 세미콜론 사용 |
| 에러 처리 | 시드 파싱 및 데이터 로드 시 안전한 fallback 기본값 처리 |
| 로깅 | 프로덕션 콘솔 오염 방지, 디버그 모드에서만 상세 로그 출력 |
| 테스트 작성 기준 | Node 내장 test runner (`node:test`, `node:assert/strict`) 활용 |
| 디렉토리 배치 | `src/` (소스코드: js, css, assets), `tests/` (단위 테스트), `docs/` (문서) |

## 검증된 명령어

성공한 원문 그대로 기록하고, 이후 변형 없이 재사용한다 (AGENTS.md 규칙). implementer는 새 행을 추가할 수 있다 — 기존 명령을 완전히 교체해야 하면(예: 패키지 매니저 변경) 옛 행을 지우지 말고 ~~취소선~~ 처리 + 교체 사유 한 줄을 남기고 새 행을 추가한다. 행 삭제는 사용자만 한다(AGENTS.md 문서 소유권).
